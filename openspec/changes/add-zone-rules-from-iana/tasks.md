# Tasks

All source paths are under `packages/client/`. Commands run from `packages/client/` unless they start with `pnpm --filter` or `git`, which run from the repository root.

- **Running tests:** one command at a time, never in the background. Vitest collects only `src/**/*.{test,steps}.{ts,tsx}`, so tests of `scripts/zoneRules/` live under `src/test/zoneRules/`. Mutation runs take at most 5 files per run; the report is `reports/mutation/mutation-report.json`.
- **Time in tests:** only `fakeClock` / `createSwitchableClock`. Never `vi.setSystemTime()` or `vi.useFakeTimers()`. Temporal is always imported from `@/lib/temporal`; `temporal-polyfill` is inlined in Vitest, so a fresh import after `vi.resetModules()` re-evaluates it and sees the installed wrapper (design D10).
- **Traceability:** every new test, step file, feature and production module names `add-zone-rules-from-iana` with its id (`@add-zone-rules-from-iana @FR-X` tags, `// @add-zone-rules-from-iana @FR-X` before `f.Scenario`, `Implements FR-X of add-zone-rules-from-iana` in JSDoc).
- **File size:** every new or changed file stays under 200 lines; each task's verification includes `wc -l` on the files it creates or changes.
- **Glossary first:** a task that names a new concept uses the term of task 2.2; `.claude/rules/glossary.md` applies.
- **Design references:** "design Dn" refers to `design.md`.
