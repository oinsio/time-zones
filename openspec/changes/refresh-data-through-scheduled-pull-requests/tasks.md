# Tasks

Paths are relative to `packages/client/` unless they start with `docs/`, `.github/` or `README`. Run tests strictly one command at a time and never in the background (`CLAUDE.md`). Every new production file gets a JSDoc line `Implements <ids> of refresh-data-through-scheduled-pull-requests (D<n>).`, every test file a `// Verifies <ids> of refresh-data-through-scheduled-pull-requests.` comment, and every Gherkin scenario the tags `@refresh-data-through-scheduled-pull-requests @<id>`. Use the glossary terms: data refresh, zone rules publication, city data refresh, data refresh pull request, data-only commit, refresh guard. Keep every file under 200 lines. Vitest collects only `src/**/*.{test,steps}.{ts,tsx}`, so the tests of `scripts/dataRefresh/` live under `src/test/dataRefresh/`. The scripts run under Node's type stripping: no `enum` or `namespace`. The implement stage never edits `.github/`, `docs/adr/`, `CLAUDE.md` or the root READMEs; those edits are the handoff patches of group 6, written to `temporary-docs/gnomish/<task>/handoff/` as `.gnomish/stages/specify/handoff.md` describes. No file under `src/` outside `src/test/` changes (M6).
