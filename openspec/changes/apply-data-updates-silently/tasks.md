# Tasks

Paths are relative to `packages/client/` unless they start with `docs/` or `.github/`. Run tests strictly one command at a time and never in the background (`CLAUDE.md`). Every new or touched production file gets a JSDoc line `Implements <ids> of apply-data-updates-silently (D<n>).`, every touched test file a `// Verifies <ids> of apply-data-updates-silently.` comment, and every new or changed Gherkin scenario the tags `@apply-data-updates-silently @<id>` (keep the tags it already has). Use the glossary terms: app revision, waiting build, silent update, watched zone, update notice, zone rules update notice, update recheck, stored release, active release, city data attribution. Keep every file under 200 lines. Vitest collects only `src/**/*.{test,steps}.{ts,tsx}`, so the tests of `scripts/appRevision/` live under `src/test/appRevision/`. The scripts run under Node's type stripping: no `enum` or `namespace` in `scripts/`. The implement stage never edits `.github/`, `docs/adr/` or `CLAUDE.md`; those edits are the handoff patches of group 9.
