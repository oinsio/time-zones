# Tasks

Paths are relative to `packages/client/` unless they start with `docs/` or `temporary-docs/`. Run tests strictly one command at a time and never in the background (`CLAUDE.md`). Every new or touched production file gets a JSDoc line `Implements <ids> of add-city-coordinates-to-locations (D<n>).`, every touched test file a `// Verifies <ids> of add-city-coordinates-to-locations.` comment, and every new or changed Gherkin scenario the tags `@add-city-coordinates-to-locations @<id>` (steps: the comment `// @add-city-coordinates-to-locations @<id>` before `f.Scenario`). Use the glossary terms: coordinates, zone coordinates, city record, zone city, city data, location. Keep every file under 200 lines. Tests of `scripts/cityData/` live under `src/test/cityData/`, tests of `scripts/zoneRules/` under `src/test/zoneRules/`. Scripts run under Node's type stripping: no `enum` or `namespace` in `scripts/`. Each implementation task is RED (failing test shown) then GREEN. `<task>` below is `github-oinsio-time-zones-135`.
