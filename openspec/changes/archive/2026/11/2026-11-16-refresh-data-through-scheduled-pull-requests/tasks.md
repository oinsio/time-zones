# Tasks

Paths are relative to `packages/client/` unless they start with `docs/`, `.github/`, `temporary-docs/` or `CLAUDE.md`. `<task>` is the branch name without its `gnomish/` prefix. Run tests strictly one command at a time and never in the background (`CLAUDE.md`). Every new production file gets a JSDoc line `Implements <ids> of refresh-data-through-scheduled-pull-requests (D<n>).`, every test file a `// Verifies <ids> of refresh-data-through-scheduled-pull-requests.` comment, and every Gherkin scenario the tags `@refresh-data-through-scheduled-pull-requests @<id>` (with the comment `// @refresh-data-through-scheduled-pull-requests @<id>` before its `f.Scenario`). Use the glossary terms: data refresh, data refresh bot, zone rules publication, city data refresh, data refresh pull request, data-only commit, refresh guard. Keep every file under 200 lines. Vitest collects only `src/**/*.{test,steps}.{ts,tsx}`, so the tests of `scripts/dataRefresh/` live under `src/test/dataRefresh/`, as those of `scripts/cityData/` live under `src/test/cityData/`. The scripts run under Node's type stripping: no `enum` or `namespace`; constants are `as const` objects. The implement stage never edits `.github/`, `docs/adr/` or `CLAUDE.md`; those edits are the handoff patches of group 6, written to `temporary-docs/gnomish/<task>/handoff/` as `.gnomish/stages/specify/handoff.md` describes. No file under `src/` outside `src/test/` changes (M6).
