# Tasks

The three changes this one builds on, `support-legacy-ios-12-safari`, `set-home-location-and-show-differences` and `show-here-entry-for-device-time`, are archived. The owners below were checked on `main` (design, Context).

All source paths are under `packages/client/src/`. Commands run from `packages/client/` unless they start with `pnpm --filter`, `git` or say "from the repository root".

- **Running tests:** one command at a time, never in the background. Stryker runs only with `--mutate`, at most 5 files per run; the report is in `reports/mutation/mutation-report.json`.
- **Time in tests:** only `fakeClock(instant, timeZone)` of `@/lib/temporal` or `createSwitchableClock` (`test/switchableClock.ts`). Never `vi.setSystemTime()` or `vi.useFakeTimers()`. Writes are observed with `createManualWriteScheduler()` (`test/writeSchedulers.ts`).
- **E2E runs:** Playwright runs the specs that `bddgen` generates, so every Playwright command after a `.feature` edit starts with `npx bddgen -c playwright.bdd.config.ts && ` (the order of the `test:bdd` script).
- **No BigInt:** no BigInt literal, `BigInt(` or `epochNanoseconds` in production code; `test/noBigIntInSources.test.ts` stays green.
- **Traceability:** every new or changed test, step file and feature carries `add-wall-time-input-with-hint`:
  - `@add-wall-time-input-with-hint @FR-X` tags above scenarios, and `// @add-wall-time-input-with-hint @FR-X` before `f.Scenario`;
  - `// Verifies NFR-X of add-wall-time-input-with-hint` in E2E steps;
  - `Implements FR-X of add-wall-time-input-with-hint` in the JSDoc of new or changed production code.
- **Glossary:** names come from `docs/glossary/` and the new terms of the proposal (wall-time input, wall-time target, wall-time hint, gap note, wall-clock time, wall-clock status). Never "time picker", "time edit", "slider" for the input, or `GMT` in new text.
- **File size:** every file stays under 200 lines. "design Dn" refers to `design.md`.
